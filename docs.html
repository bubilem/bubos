    1. Úvod a rychlý start

    BubOS je výukový simulátor Linuxu, který běží celý ve vašem prohlížeči. Nic se neinstaluje a nic se neposílá na server – „počítač“ je jen program v JavaScriptu, který předstírá, že je Linux. Můžete tedy bez obav zkoušet i příkazy, které by na skutečném stroji něco rozbily (například rm -r /): kdyby se něco pokazilo, tlačítko Přeinstalovat vrátí systém do výchozího stavu.

    Simulátor je výukový: chová se jako Linux (příkazy se jmenují stejně, mají stejné volby a podobné hlášení), ale není to dokonalá kopie. Co není podporováno, je u příslušné části výslovně uvedeno.

    Přihlášení

    Systém tě po spuštění automaticky přihlásí jako uživatele student. Další účet je root (správce). Po příkazu exit se objeví přihlašovací výzva.

    UživatelHesloPoznámka
    studentstudentběžný uživatel, člen skupiny sudo (smí používat sudo)
    rootrootsprávce, smí všechno

    Prvních pět minut

    student@bubos:~$ pwd                     # kde jsem?
/home/student
student@bubos:~$ ls                      # co tu je?
Documents  Downloads  README.txt
student@bubos:~$ cd Documents           # přejdi do složky
student@bubos:~/Documents$ cat pisen.txt   # vypiš soubor
student@bubos:~/Documents$ grep ERROR log.txt | wc -l   # kolik je v logu chyb?
student@bubos:~/Documents$ man ls              # manuál k příkazu
student@bubos:~/Documents$ help                # přehled všech příkazů

    Příkazy se zadávají anglicky, stejně jako v opravdovém Linuxu. Nápověda a chybová hlášení jsou česky nebo anglicky podle přepínače CS / EN v horní liště (nebo příkazem lang).

    3. Jak systém funguje

    BubOS je poskládaný z několika vrstev. Každá vrstva smí používat jen vrstvy pod sebou, takže se dá jádro testovat bez prohlížeče.

    ┌────────────────────────────────────────────────────────────┐
│  index.html + css/bubos.css          stránka a vzhled        │
├────────────────────────────────────────────────────────────┤
│  js/main.js    start, přihlášení, hlavní smyčka, tlačítka    │
├───────────────────────────┬────────────────────────────────┤
│  js/ui/                   │  js/os/linux/                   │
│  terminál, pager, editor  │  profil Linuxu: seznam příkazů, │
│  (DOM)                    │  PATH, prompt, výchozí soubory, │
│                           │  commands/*.js (1 příkaz = 1)   │
├───────────────────────────┴────────────────────────────────┤
│  js/core/    JÁDRO – bez DOM, testovatelné v Node            │
│  vfs · users · shell/ · streams · process · storage · i18n   │
└────────────────────────────────────────────────────────────┘
  i18n/ (hlášení cs, en)    man/ (manuálové stránky cs, en)

    Co se stane po zadání příkazu

    Například grep ERROR log.txt | wc -l:

    1. Terminál (ui/terminal.js) přečte řádek a předá ho main.js.
    2. Shell (core/shell/shell.js) provede expanzi historie (!!) a zapíše řádek do historie.
    3. Parser (parse.js) rozloží řádek na příkazy, roury a přesměrování; aliasy rozvine už tady.
    4. Pro každý příkaz v rouře se vytvoří simulovaný proces (PID z tabulky procesů) a všechny běží souběžně, spojené rourami (streams.js).
    5. Slova se expandují (expand.js): ~, $PROMENNA, $(příkaz), hvězdičky *.txt.
    6. Shell najde příkaz: nejdřív vestavěné (cd, echo…), pak soubor v adresářích z PATH (/usr/local/bin:/usr/bin:/bin). V souborovém systému kontroluje práva (potřebujete právo x).
    7. Soubor v /usr/bin je jen „stub“ s jedním řádkem #!bubos:grep; podle něj se načte modul js/os/linux/commands/grep.js a zavolá se jeho funkce run(ctx).
    8. Výstup příkazu putuje rourou do dalšího; poslední příkaz píše do terminálu. Návratový kód se uloží do $?.

    Procesy

    Každý spuštěný příkaz dostane číslo procesu (PID). ps ukazuje i několik „systémových“ procesů (init, cron, sshd…), které jsou jen dekorace. Příkazem kill nebo klávesou Ctrl+C se běžící příkaz přeruší. Tabulka procesů se neukládá do exportu.

    Předdefinované proměnné: HOME, USER, LOGNAME, SHELL, PATH, PWD, OLDPWD, HOSTNAME, TERM, LANG.

    Aliasy

    alias ll='ls -l' vytvoří zkratku, unalias ll ji zruší. Výchozí aliasy (z ~/.bashrc): ll, la, .., grep s barvou.

    Historie

    • Příkazy se ukládají do ~/.bash_history (tedy i do exportu) a listuje se v nich šipkami; history je vypíše.
    • !! zopakuje poslední příkaz, !5 příkaz číslo 5, !ls poslední příkaz začínající na ls.
    • Řádek začínající mezerou se do historie neuloží.

    Skripty a ~/.bashrc

    Textový soubor s příkazy (jeden na řádek) můžete spustit třemi způsoby: source skript.sh (v aktuálním shellu), nebo mu dát právo spuštění chmod +x skript.sh a zavolat ./skript.sh (ve vlastním podřízeném shellu, s argumenty v $1, $2…). Při každém přihlášení se automaticky provede ~/.bashrc – tam jsou aliasy a export EDITOR=nano.

    Co zatím neumí

    Podmínky a cykly (if, for, while), funkce, aritmetiku $((…)), jobs/fg/bg a tvrdé odkazy (ln bez -s). Jsou v plánu další iterace (viz docs/PROJEKT.md).

    5. Souborový systém

    Souborový systém je celý v paměti prohlížeče jako strom JSON objektů. Každý uzel (soubor, adresář, odkaz) má typ, práva (mode), vlastníka (uid), skupinu (gid) a čas změny. Soubor navíc obsahuje text, adresář seznam potomků, odkaz cíl. Soubor smí mít nejvýše 1 MiB. Strom začíná kořenem /; oddělovačem je lomítko.

    Cesty

    • Absolutní začíná lomítkem: /etc/passwd. Relativní se počítá od aktuálního adresáře: Documents/log.txt.
    • . = aktuální adresář, .. = nadřazený, ~ = váš domov, cd - = zpět do předchozího.
    • Velká a malá písmena se rozlišují: Soubor.txt a soubor.txt jsou dva různé soubory.

    Přístupová práva

    Každý soubor má tři trojice práv: pro vlastníka, skupinu a ostatní. Každé právo je r (čtení, 4), w (zápis, 2), x (spuštění, 1). Zápis -rwxr-x--- tedy znamená: vlastník smí vše, skupina čte a spouští, ostatní nic. Číselně: 750. U adresáře znamená r vypsat obsah, w vytvářet a mazat v něm, x do něj vstoupit. Správce root obchází čtení a zápis; spustit smí jen soubory s nějakým x. Měnit práva smí vlastník (chmod) nebo root, vlastníka mění (chown) jen root.

    Sticky bit (t na konci práv, např. u /tmp): mazat nebo přejmenovávat soubory v adresáři smí jen jejich vlastník, vlastník adresáře a root.

    Nové soubory dostanou práva 644 a adresáře 755 (umask 022).

    6. Uživatelé a práva

    Uživatelé jsou stejně jako v Linuxu uložení v textových souborech – můžete si je vypsat příkazem cat.

    SouborObsah
    /etc/passwdjeden řádek na uživatele: jméno:x:UID:GID:popis:domov:shell
    /etc/groupskupiny: jméno:x:GID:členové
    /etc/shadowhesla uložená jako otisk (hash). V BubOS je hashování jen symbolické – jde o výuku, ne o bezpečnost

    Předvytvoření uživatelé: root (UID 0), systémoví (daemon, bin, sys, www-data, nobody – nelze se jimi přihlásit) a student (UID 1000, skupiny student, users, sudo).

    • whoami, id, groups – kdo jsem a v jakých skupinách.
    • su uživatel – přepne uživatele (zeptá se na jeho heslo); su - navíc nahraje jeho prostředí. exit vrací zpět.
    • sudo příkaz – provede příkaz jako root. Smí jen členové skupiny sudo, zeptá se na vaše heslo a 5 minut si ho pamatuje (sudo -k zapomene).
    • sudo useradd -m alice – vytvoří uživatele (s -m i domovský adresář podle /etc/skel); sudo passwd alice nastaví heslo.

    Co zkusit: jako student vypište cat /etc/shadow (nepovede se: Permission denied), pak sudo cat /etc/shadow (povede).

    7. Ukládání, export a import

    Žádná data se neposílají na server. Server (PHP, Python…) pouze doručí statické soubory.

    • Automatické ukládání: každá změna se asi 0,4 s po ní uloží do databáze prohlížeče (IndexedDB bubos; záložně localStorage). Ukládá se také při zavření nebo přepnutí záložky. Po obnovení stránky se vše načte zpět.
    • Důsledek: data jsou svázaná s konkrétním prohlížečem a počítačem. Na jiný počítač je přenesete tlačítky Export a Import. Smazání dat prohlížeče smaže i váš systém, proto exportujte důležitou práci.
    • Import přijímá jen platný soubor BubOS do 20 MB; obsah se před použitím zkontroluje a nikdy se nevkládá do stránky jako HTML.
    • Přeinstalovat smaže uložený stav a vytvoří nový systém (jazyk zůstane).

    {
  "format": 1,                    // verze formátu

  "os": "linux",                  // typ systému
  "savedAt": "2026-11-13T10:15:00.000Z",
  "settings": { "lang": "cs", "theme": "dark" },

    9. Pro vývojáře

    Spuštění

    Stačí libovolný statický server ve složce projektu (moduly ES nefungují po otevření souboru přes file://):

    python -m http.server 8080      # nebo: php -S localhost:8080
# potom otevřít http://localhost:8080
# Windows: dvojklik na start.bat

    Testy: npm test (Node 18+, bez závislostí).

    Přidání nového příkazu

    1. Vytvořte js/os/linux/commands/jmeno.js: 
      export default {
  async run(ctx) {
    // ctx.args = argumenty, ctx.stdin / ctx.stdout / ctx.stderr, ctx.fs, ctx.user, ctx.env, ctx.tty …
    await ctx.stdout.write('ahoj\n');
    return 0;              // návratový kód
  },
};
    2. Přidejte jméno do pole COMMANDS v js/os/linux/profile.js. Příkaz, který musí běžet přímo v shellu (mění jeho stav), přidejte i do SHELL_ONLY v profile.js a skeleton.js.
    3. Napište stránku #### jmeno do man/cs.txt i man/en.txt. První řádek pod JMÉNO / NAME je jmeno - popis; ten se objeví v help i v této příručce.
    4. Přidejte překlady hlášení do i18n/cs.json i i18n/en.json a test do tests/shell.test.js.

    Chyby se hlásí výjimkou throw new CmdError('text', kód) ve formátu GNU (program: operand: zpráva). Dlouhé smyčky mají volat ctx.check(), aby šly přerušit Ctrl+C.

    Podrobnosti viz docs/ARCHITEKTURA.md a docs/PROJEKT.md (plán: sed, awk, if/for/while, síť, lekce, profil Windows).
